## MCSM面板到底能做什么

它解决的问题很具体：Minecraft 服务端是个命令行程序，原生的操作方式是 SSH 进去敲指令，换存档、加 mod、看报错都得记路径。MCSM 把这些动作搬到网页上，文件管理、终端、实例设置都做成按钮。

官方 README 列出的能力包括：通过内置应用市场一键部署 Minecraft 或 Steam 游戏服务器；兼容 Palworld、Squad、Project Zomboid、Terraria 等大部分 Steam 游戏；支持 Docker 容器运行，也支持直接以进程方式运行；分布式架构，一个网页面板可以管理多台物理机或虚拟机；带多用户权限系统，管理员可以创建普通用户并把实例分配给他们，普通用户只能碰分配给自己的实例。

技术栈比较轻，整个项目用 TypeScript 开发，运行环境只要 Node.js 16.20.2 或更高版本，不需要装数据库。面板分 web 端和 daemon 端两个进程，web 端管用户、节点连接和 API，daemon 端管实例进程、Docker 操作和文件系统。默认 web 端口 23333，daemon 端口 24444。浏览器支持 Chrome、Firefox、Safari、Opera，IE 已经不支持。

对普通玩家来说，最实用的两点是文件管理和多用户。前者让你不用记 `scp` 和 `unzip` 就能传存档；后者让你把服开给朋友时，不用把 root 密码交出去。

## 自己装的话，MCSM面板怎么装

官方给了三条安装路径，按操作系统选。

**Windows** 最省事，下载整合包解压，双击 `start.bat`，web 面板和 daemon 进程一起启动。

**Linux** 有一行命令：

bash
sudo su -c "wget -qO- https://script.mcsmanager.com/setup.sh | bash"


这条脚本只适用于 Ubuntu、CentOS、Debian、Archlinux，面板代码和运行环境会自动装到 `/opt/mcsmanager/` 目录。装完用 `systemctl start mcsm-{web,daemon}` 启动，`systemctl stop mcsm-{web,daemon}` 停止。如果一行命令失败，可以手动装：下载 Node.js、建目录、下载 release 包、跑 `install.sh`，再分别启动 daemon 和 web。手动方式不会自动注册成系统服务，需要自己用 `screen` 或 `tmux` 保活。

**Docker** 方式需要写 `docker-compose.yml`，把里面所有 `<CHANGE_ME_TO_INSTALL_PATH>` 换成实际安装目录。装完之后 web 端可能无法自动连上 daemon，需要手动新建一个节点把两端接起来，这一步官方文档专门提醒过。如果你用的是 rootless Docker，socket 路径不是 `/var/run/docker.sock`，而是 `/run/user/<uid>/docker.sock`，要改挂载并设置 `DOCKER_HOST`。

装完在浏览器访问 `http://你的服务器IP:23333/`。访问不了先查三件事：安全组有没有放行 23333、web 和 daemon 是不是都启动了、服务器有没有公网 IP。

## 换存档和加mod：两个最常踩的坑

这两件事在网页面板上点几下就能做，但失败率很高，原因集中在两个地方。

**换存档的权限问题。** 操作本身是三步：把本地存档上传到服务器、删掉原来的 `world` 文件夹、把上传的文件夹改名成 `world`。命令大概是：

bash
sudo yum install unzip -y
rm -rf world/
mv 你的存档文件夹名/ world


坑在后面。如果你按教程建了一个专用用户（比如 `mcfabricuser`）来跑服务端，换完存档后这个用户对新 `world` 文件夹没有写权限，服务端启动会失败，日志里不一定写得清楚。解决办法是把整个服务端根目录的属主改回这个用户：

bash
sudo chown -R mcfabricuser:mcfabricuser /minecraft


如果服务端是以 root 运行的，就不会遇到这个问题。判断方法很简单：看你的 systemd 服务文件里 `User=` 写的是谁。

**加 mod 不生效。** 先确认服务端类型：原版 `server.jar` 不支持任何 mod，必须换 Fabric 或 Forge 版本。然后分清两类 mod：

- 服务端 mod（比如连锁采集）：服务器和本地客户端都必须装，而且版本要一致，否则功能不生效。
- 客户端 mod（比如小地图）：只放本地 `mods` 文件夹就行，传不传到服务器都不影响使用。

还有一点，Fabric 环境下 Fabric API 是前置，不装它，其他依赖 API 的 mod 全都不会加载。官方教程的建议是本地和服务器各放一份完全相同的 mod 列表，这样最不容易出问题。

## 面板开到公网，安全上要注意什么

23333 和 24444 默认就是公网端口，扫描器几小时内就能找到。MCSM 自带多用户权限系统，但默认密码和弱密码是主要风险点。开服前至少做三件事：改掉面板默认账号密码、给普通用户分配实例而不是共享管理员账号、在安全组里把端口限制在自己常用的 IP 段。面板的分布式设计本身是为了方便管理多台机器，但这也意味着一个入口泄露可能影响多个实例。

## 常见问题

**MCSM 面板收费吗？**
面板本身开源免费，Apache 2.0 协议。花钱的是服务器、带宽和电费。

**支持哪些游戏？**
Minecraft 全系，以及大部分 Steam 游戏服务器，包括 Palworld、Squad、Project Zomboid、Terraria。理论上任何能在命令行跑的程序都能托进去。

**一定要装数据库吗？**
不用。只需要 Node.js 16.20.2 以上版本和几个解压工具。

**Windows 电脑能当服务器吗？**
能，官方有 Windows 整合包。但家用宽带通常没有固定公网 IP，外网朋友要连进来需要内网穿透，稳定性和延迟都不如云服务器。

**面板登录页打不开怎么办？**
按顺序查：web 进程是否在跑、23333 端口是否放行、访问的 IP 是否是公网 IP、Docker 部署时节点是否已手动连接。
